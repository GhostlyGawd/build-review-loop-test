# Protocol 2.8 execution report

Date: 2026-07-21

## Result

The preregistered protocol 2.8 run is **invalid**. Both neutral builders
completed successfully and were assigned only after their snapshots were
sealed, but the first treatment reviewer returned an artifact that did not
conform to the frozen review schema. The protocol therefore stopped before any
confirmatory fixer, tester, or evaluator was invoked.

An explicitly non-preregistered exploratory recovery was then completed from
the already sealed snapshots. Its fresh final reviewer reported zero actionable
findings, so the treatment loop stopped in cycle 1 without a fixer or tester and
`Tfinal` remained byte-identical to `T0`.

## Exploratory treatment recovery

The exploratory recovery was deliberately kept separate from the
preregistered result:

1. A schema-assisted reviewer launch was rejected by the provider before a
   model turn because `uniqueItems` was unsupported.
2. A fresh reviewer completed with one medium finding, but its

   and was not handed to a fixer.
3. The final allowed fresh reviewer used a provider-compatible pre-injection
   schema, passed the unchanged authoritative review schema, and returned zero
   findings.
4. The zero-findings rule stopped treatment immediately. No exploratory fixer
   or tester ran, so fixes applied = 0 and `Tfinal = T0`.

## Interpretation

This execution does not provide evidence that the review loop improves quality:

- The confirmatory run is invalid.
- The exploratory reviewer found no actionable defects in its final valid
  pass, so the loop made no code changes.
- `T0` and `Tfinal` are byte-identical, but their independently produced
  exploratory totals differ by one point. That difference is evaluator and
  recovery noise, not a treatment effect.
- The baseline outscored the treatment implementation by a large margin, but
  only two independently generated builds were sampled. Builder quality and
  evaluator behavior are confounded with the assigned arms.
- Evaluator cap arithmetic required one fresh recovery and one deterministic
  fallback, weakening score comparability.
- Every package still had public and hidden failures.

The useful dogfood result is methodological: strict artifact validation caught
real orchestration defects, and the run exposed evaluator reliability and cost
as first-class threats to this experiment design. A future confirmatory run
would need a separately frozen provider-compatible pre-injection schema and
deterministic score calculation outside the evaluator before collecting more
samples.

## Publication adjustments

The experiment artifacts and scores above were sealed before publication. To
make the selected B0 implementation a green, maintainable repository product,
the publication branch applied only post-experiment product adjustments:

- copied the five selected application source files from the sealed B0
  snapshot;
- mechanically formatted the TSX and CSS with the repository's frozen
  Prettier version;
- registered explicit React Testing Library cleanup between public test cases,
  eliminating cross-test DOM leakage that caused two full-suite-only failures;
  and
- changed the default product gate to run formatting, lint, types, the 56
  protocol semantic tests that do not assert pre-promotion repository state,
  public tests, and the production build.

The archival `npm run test:protocol` and `npm run validate:scaffold` commands
remain unchanged. They intentionally include two checks of the preregistered
pre-promotion byte inventory, so they are no longer included in `npm run check`:
promoting `src/main.tsx` necessarily changes that inventory. The product gate
runs the same frozen protocol test file while skipping only those two
repository-state assertions. These publication adjustments do not alter the
sealed candidates, treatment result, evaluation artifacts, or reported scores.

## Reproduce the promoted application

Requires Node.js 22 and npm 11.11.0:

```sh
npm ci
npm run check
npm run dev
```

The promoted browser app uses local in-memory state only. It has no backend,
authentication, persistence, network calls, credentials, or personal-data
collection.
